# أدوات مزامنة جداول الشيفتات (shift-sync)

مجموعة سكربتات لاستيراد ملفات Excel الخاصة بجداول الشيفتات إلى جداولها الصحيحة
في قاعدة البيانات — بذكاء وبأمان (معاينة قبل التنفيذ).

> ⚠️ كل السكربتات تعمل على قاعدة البيانات المحددة في `.env` (`DATABASE_URL`).
> شغّلها من مجلد الباك-إند: `/root/hodouri/bio_time_backend`.
> السكربتات دي **تكتب في قاعدة بيانات البرودكشن** لما تستخدم `--apply`.

---

## امتى تستخدم إيه؟

| الحالة | السكربت |
|---|---|
| وصلني ملفات Excel وعايز أعرف كل ملف بتاع أنهي جدول وإيه محتواه | `inspect-files.mjs` |
| عايز أشوف تفاصيل ملف واحد (القيم المسموحة + أعمدة الجدول) | `dump-raw.mjs` |
| عايز أعاين الاستيراد قبل ما ينفّذ (بدون كتابة) | `sync-grids.ts` (بدون `--apply`) |
| عايز أنفّذ الاستيراد فعليًا | `sync-grids.ts --apply` |

**دايمًا اعمل معاينة (dry-run) الأول، راجع النتيجة، وبعدين نفّذ.**

---

## 1) `inspect-files.mjs` — نظرة سريعة على كل الملفات

يقرأ كل ملفات `.xlsx` في مجلد ويطبع لكل ملف: معرّف الجدول (من ورقة `_meta`)،
التواريخ، عدد الموظفين، وقيم الشيفتات الموجودة. **قراءة فقط.**

```bash
node scripts/shift-sync/inspect-files.mjs files_to_sync/1
```

## 2) `dump-raw.mjs` — تشريح ملف واحد

يطبع ورقة «مرجع الشيفتات» (القيم الرسمية المسموحة) وأول صفوف «جدول الشيفتات»
بأرقام الأعمدة — مفيد لفهم مكان الكود/الاسم/الأيام لو الشكل اتغير. **قراءة فقط.**

```bash
node scripts/shift-sync/dump-raw.mjs "files_to_sync/1/<file>.xlsx" 8
```

## 3) `sync-grids.ts` — المزامنة الذكية (المعاينة + التنفيذ)

الأداة الأساسية. بتحدد الجدول الهدف لكل ملف، تتحقق من الموظفين والقيم، وتستورد.

### تحديد الجدول الهدف
1. من ورقة `_meta` لو موجودة (`shift_grid_id`).
2. لو الملف مفيهوش `_meta`: يحل الجدول **بالاسم + التواريخ** من اسم الملف
   (النمط: `<Name>_<YYYY-MM-DD>_<YYYY-MM-DD>_<Dept>.xlsx`)، وبعدين يختم `_meta` تلقائيًا.

### تحويل القيم القديمة (Legacy labels)
بعض الملفات بتستخدم قيم قديمة زي `SH 7 M - شيفت ٧ صباحي`. السكربت بيحوّلها
لأكواد الشيفتات الحالية عبر جدول `LEGACY_LABEL_MAP` جوا السكربت:

| القيمة القديمة | الكود الحالي |
|---|---|
| `SH 6 M …` (صباحي) | `O.6` |
| `SH 7 M …` (صباحي) | `O.7` |
| `SH 8 M …` (صباحي) | `O.8` |
| `SH 11 N …` (ليلي) | `C.11` |

> القاعدة العامة: الصباحي `SH h M → O.h` ، الليلي `SH h N → C.h`.
> لو ظهرت قيمة قديمة جديدة، ضيفها في `LEGACY_LABEL_MAP` أعلى الملف.

### تصحيح أكواد موظفين
لو الإكسيل فيه كود غلط لموظف موجود، ضيفه في `CODE_REMAP` أعلى السكربت
(مثال: كليفن دوبيزل `495 → 1050`).

### الأوامر

```bash
# معاينة فقط (لا يكتب أي شيء) — النتيجة بتوضح الجداول والموظفين الناقصين وأي قيم غير معروفة
npx ts-node scripts/shift-sync/sync-grids.ts files_to_sync/1

# تنفيذ الاستيراد فعليًا
npx ts-node scripts/shift-sync/sync-grids.ts files_to_sync/1 --apply

# تنفيذ + إنشاء الموظفين غير الموجودين في القاعدة قبل الاستيراد
npx ts-node scripts/shift-sync/sync-grids.ts files_to_sync/1 --apply --create-missing
```

### قراءة نتيجة المعاينة
- `grid` : الجدول الهدف وحالته (`grid` = قابل للتعديل، `confirmed` = مؤكد ومقفول).
- `employees (متطابق X / ناقص Y)` : كام موظف موجود في القاعدة وكام ناقص.
- `missing` : أكواد الموظفين غير الموجودين (استخدم `--create-missing` لإنشائهم).
- `labels — غير معروف` : أي قيم شيفت مش متعرفة. **لازم تبقى 0** قبل التنفيذ،
  وإلا الملف مش هيتستورد (ضيف تحويلها في `LEGACY_LABEL_MAP`).
- `blocking issues` : أي مشاكل بتمنع التنفيذ (جدول مؤكد / غير موجود / قيم غير معروفة).

### أمان
- بدون `--apply` مفيش أي كتابة إطلاقًا.
- الجداول المؤكدة (`confirmed`) بتترفض — لازم تفتحها للتعديل الأول.
- الاستيراد بيأثر على صفوف الموظفين الموجودة في الملف فقط.
